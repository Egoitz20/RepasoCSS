1. Catálogo y Uso Correcto de Inputs Semántica HTML5

Elegir el atributo type adecuado es fundamental para que los dispositivos móviles desplieguen el teclado virtual correcto y el navegador aplique validaciones sintácticas automáticas:

Tipo de Input Propósito y Características Teclado Móvil / Comportamiento Nativo
type="text" Campos de texto libre de una sola línea (nombre, alias, apellidos). Teclado alfanumérico estándar.
type="email" Direcciones de correo electrónico. Valida automáticamente la presencia de @ y dominio. Despliega tecla rápida de @ y .com en móviles.
type="password" Contraseñas y credenciales sensibles. Ofusca los caracteres mediante puntos o asteriscos. Teclado seguro sin sugerencias de autocorrección pública.
type="number" Valores numéricos cuantificables (edad, ki de combate, cantidad). Admite min, max y step. Despliega teclado numérico directo de diez dígitos.
type="date" Selección de fechas (nacimiento, fecha del torneo). Formato uniforme ISO YYYY-MM-DD. Abre el selector de calendario nativo del sistema operativo.
type="checkbox" Opciones booleanas independientes (aceptar condiciones, habilidades aprendidas). Permite seleccionar 0, 1 o múltiples casillas.
type="radio" Selección mutuamente excluyente entre varias opciones que comparten el mismo atributo name. Solo permite tener una única opción activa en el grupo.
type="submit" Botón de envío semántico que dispara la validación y el despacho del formulario. Activa el evento submit nativo.

2. Las 6 Reglas de Oro en Formularios UX & Accesibilidad

1. Asociación Estricta <label> con `for` e `id`

Todo campo debe tener un <label for="campo-id"> cuyo valor coincida exactamente con el id="campo-id" del input. Beneficio ergonómico: hacer clic sobre el texto del label coloca el foco en el input o marca el checkbox.

2. El Placeholder NO es un Label

Prohibido usar placeholders como única etiqueta. El placeholder desaparece tan pronto como el usuario empieza a escribir, provocando pérdida de contexto, y no es leído confiablemente por lectores de pantalla.

3. Validaciones Nativas y CSS :valid/:invalid

Aprovecha atributos como required, minlength y pattern. Usa la pseudoclase moderna :user-invalid para teñir de rojo el borde únicamente después de que el usuario haya interactuado con el campo.

4. Foco Accesible (:focus-visible)

¡Nunca apliques outline: none; sin alternativa! Las personas que navegan mediante teclado necesitan un anillo de foco visible y nítido (por ejemplo: box-shadow: 0 0 0 3px rgba(25, 114, 185, 0.3);).

5. Accesibilidad Básica (A11y)

Contraste de color superior a 4.5:1 (WCAG AA), indicaciones claras de campos obligatorios mediante asteriscos o textos descriptivos, y orden lógico de tabulación.

6. Maquetación con CSS Grid

Organiza los grupos de campos en una cuadrícula con gap: 20px que se adapte fluidamente a una sola columna vertical en dispositivos móviles. 

/* Estilos profesionales recomendados para campos de formulario */
.form-control {
  width: 100%;
  padding: 10px 14px;
  border: 1.5px solid var(--color-borde);
  border-radius: 8px;
  font-family: inherit;
  transition: border-color 0.2s ease, box-shadow 0.2s ease;
}

/* Foco visible sin eliminar accesibilidad */
.form-control:focus-visible {
  outline: none;
  border-color: var(--color-acento);
  box-shadow: 0 0 0 3px rgba(25, 114, 185, 0.25);
}

/* Validación amigable que no asusta al usuario antes de escribir */
.form-control:user-invalid {
  border-color: var(--color-rojo);
  background-color: var(--color-rojo-fondo);
}
